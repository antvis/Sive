# Sive 产品功能说明

## 1. 文档目的

本文用于描述 Sive 桌面端的目标产品形态、核心功能和业务规则，为后续产品设计与 AI 辅助开发提供上下文。

文中分为两类范围：

- **目标 MVP**：产品计划完整交付的最小可用版本。
- **当前开发阶段**：当前优先完成的本地持久化能力，不代表最终产品能力。

## 2. 产品背景

AVA 4.0 已提供数据加载、语义层、分析和可视化等 Data Agent 基础能力，但周边应用生态仍不完善。

Sive Web 已具备图表、报告和数据分析能力，但业务数据敏感、远程服务顾虑以及使用成本会影响用户采用。桌面端作为平行产品，强调本地运行、用户自带模型服务和开源演进。

## 3. 产品定位

> 以数据为起点、由 AI 辅助完成分析，并能保存和交付成果的桌面工作台。

面向需要处理业务文件、数据库或在线表格的用户，使用户不必先学习 SQL，也能浏览数据、提出问题、核对分析依据并保存结论。熟悉 SQL 的用户可以进一步检查计算过程。

### 产品价值

- 本地桌面运行，降低敏感数据上传顾虑。
- 作为 AVA 的开源生态应用，提供可直接使用的数据分析工作台。
- 用户配置自己的模型服务，由用户承担模型调用成本。
- 与 Sive Web 形成桌面端和 Web 端的互补，而非重复建设所有能力。

## 4. 产品原则

- **开源**：使用 Sive 名称和仓库，便于社区持续演进。
- **轻量**：聚焦数据源管理、对话分析和洞察收藏，不建设完整 BI 平台。
- **本地优先**：业务数据、分析记录和应用设置优先保存在本地。
- **简洁高质量**：页面、交互和代码均保持简单，不为假想需求增加配置和抽象。
- **可核对**：AI 结论应能查看数据结果和计算依据，而不是只展示一段文本。
- **凭据安全**：数据库密码和模型 Key 不明文展示或存储。

## 5. 目标用户与场景

### 目标用户

- 需要快速理解业务数据的运营、产品和业务人员。
- 需要辅助探索数据、检查 SQL 和生成图表的分析师与研发人员。
- 重视数据本地化，希望自行控制模型服务和调用成本的用户。

### 典型场景

- 查看一份业务文件，快速了解字段、数据分布和关键指标。
- 围绕一个数据源连续提问，保留完整分析上下文。
- 检查 AI 生成的数据结果、图表和 SQL。
- 收藏有价值的一次分析，形成可回看的洞察片段。
- 归档不再活跃的分析，并在需要时恢复。

## 6. 核心使用流程

**加入数据 → 浏览与筛选 → 选择模型和分析方式 → 提问分析 → 核对结果 → 收藏洞察。**

目标 MVP 不以分享为前置闭环；导出、报告和分享能力可后续独立规划。

## 7. 信息架构

### 整体布局

- 左侧上方：新建分析、数据源、洞察 Snippet 等主导航。
- 左侧中间：分析会话列表，支持切换和管理历史分析。
- 左侧下方：软件设置。
- 右侧内容区：展示当前页面。
- 对话分析页：左侧为对话和分析结果，右侧为当前数据源的信息面板。
- 已打开的数据源或分析可通过顶部 Tab 切换，避免重复打开。

### 四个核心页面

1. 数据源页面
2. 对话分析页面
3. 洞察 Snippet 页面
4. 软件设置页面

## 8. 功能说明

### 8.1 数据源页面

#### 数据源列表

- 无数据源时展示空状态和可用的数据源类型，引导用户创建第一个数据源。
- 已有数据源时以卡片列表展示名称、类型、更新时间和基本状态。
- 点击数据源卡片进入对应的数据浏览和对话分析页面。

#### 添加数据源

- 目标 MVP 优先支持本地业务文件，规划格式包括 CSV、JSON、XLSX 和 Parquet。
- MySQL 等数据库连接作为数据源扩展能力，按开发阶段接入。
- 创建成功后保存数据源元数据、连接信息和必要的语义信息。
- 数据源连接或导入失败时保留用户输入，并提供明确错误信息。

#### 数据源管理

- 重命名数据源。
- 删除数据源；删除不应意外清除仍需保留的历史分析内容。
- 对文件移动或连接失效等异常状态给出提示。
- 当前阶段只实现数据源元数据的保存、修改、查询和删除，不实现文件解析或数据库连接。

#### 数据与语义面板

数据源详情区域包含：

- **数据**：表格预览、分页或滚动加载、基本筛选。
- **字段**：字段名称、类型及基本统计信息。
- **语义层**：业务说明和指标定义，支持编辑保存。

语义层的用途是帮助用户和 AI 理解业务字段，不要求用户掌握 SQL。

### 8.2 对话分析页面

#### 会话

- 用户基于一个数据源创建分析会话。
- 会话保存用户问题、AI 回复、分析结果、模型名称和分析方式。
- 新会话可使用默认标题，第一次提问后以问题作为标题。
- 支持重命名、归档、恢复和永久删除。
- 归档会话不出现在默认会话列表中，可在设置页恢复。
- 永久删除仅针对已归档会话，并同时删除其消息和关联 Snippet；数据源不受影响。

#### 提问

- 无历史消息时可展示推荐问题，帮助用户开始分析。
- 输入区支持选择已配置的模型。
- 分析方式包括：
  - **直接分析**：适合明确、单次即可完成的问题。
  - **多步探索**：适合需要多次查询和逐步验证的问题。
- 同一会话中的问题应保留上下文。

#### 分析结果

一次完整分析可以包含：

- 自然语言结论。
- 查询或计算得到的数据结果。
- 一个或多个可视化图表。
- 可展开查看的计算依据，包括 SQL 或分析过程。
- 必要的警告，例如结果截断、数据不足或需要用户核对假设。

分析结果需要持久化，重新打开应用后仍可查看。

#### 收藏分析

- 每次完成的分析都可以收藏为 Snippet。
- 同一次分析最多保留一个有效 Snippet，重复收藏不产生重复卡片。
- 收藏保存标题和展示内容快照，避免后续会话变化影响已保存内容。

### 8.3 洞察 Snippet 页面

- 以卡片形式展示用户收藏的分析。
- 卡片包含标题、来源数据源、更新时间和主要图表或结论。
- 支持查看详情和原始分析内容。
- 支持重命名和取消收藏。
- 取消收藏不删除原始分析会话。

刷新、重新生成、HTML/PDF/PNG 导出和分享不属于当前持久化阶段，后续按独立需求评估。

### 8.4 软件设置页面

#### 通用设置

- 界面主题：浅色或深色。
- 数据预览的默认分页行数可在后续需要时加入，不预先增加无实际用途的配置。

#### 分析设置

- 默认分析方式：直接分析或多步探索。
- DuckDB 或 AVA 实例参数只有在真实分析能力接入时再提供，不提前建设配置项。

#### 模型服务

- 添加、编辑和删除兼容 OpenAI 协议的模型服务。
- 配置服务名称、Base URL、API Key 和可用模型列表。
- 支持设置默认模型服务及默认模型。
- API Key 使用系统加密能力保存，界面只展示是否已配置，不回显密钥。
- 删除当前默认服务后清除默认选择。
- 模型发现、连通性测试和实际模型调用属于后续接入能力，不与本地配置持久化混合实现。

#### 已归档分析

- 按数据源展示已归档会话。
- 支持搜索、恢复和永久删除。
- 永久删除需要明确的二次确认。

## 9. 核心产品对象

| 对象           | 含义                             | 关键规则                             |
| -------------- | -------------------------------- | ------------------------------------ |
| Dataset        | 一个可分析的数据源及其元数据     | 包含类型、配置、字段信息、语义和指标 |
| Conversation   | 围绕某个数据源的一次持续分析会话 | 可归档、恢复和永久删除               |
| Message        | 会话中的用户问题或 AI 回复       | 按顺序保存，用户问题与分析回复相关联 |
| Analysis Run   | 一次完整提问及其分析结果         | 保存问题、输出、模型、分析方式和时间 |
| Snippet        | 从一次分析收藏的洞察快照         | 一次分析最多一个有效收藏             |
| Model Provider | 用户配置的模型服务               | 保存服务与模型配置，敏感 Key 加密    |
| Settings       | 主题、默认模型等本地设置         | 应用重启后保持                       |

这些名称用于统一产品沟通，不要求机械映射为同名类、表或接口。

## 10. 当前开发阶段边界

当前优先完成 Electron main 的本地持久化闭环：

- 数据库初始化与连接生命周期。
- 数据源元数据、会话、消息、分析结果、Snippet、设置和模型配置的本地读写。
- 支撑上述读写的 Service 和 IPC。
- IPC 只承担进程通信和必要的输入校验，不沿用旧设计扩展额外体系。
- main 启动时复用同一个数据库实例和同一套 Repository，不在各 Service 中重复创建数据库连接或 Repository。

当前明确不实现：

- AVA Agent、AI SDK Agent 和模型实际调用。
- 流式分析任务、取消任务和任务进度状态机。
- 文件选择、文件解析、数据预览查询和 MySQL 连接。
- AVA 推荐问题、自动语义生成和 DuckDB 分析。
- 图表刷新、导出、报告和分享。

未接入的能力不写伪成功逻辑，也不为了保持旧接口而保留空实现。

## 11. 目标 MVP 验收标准

目标 MVP 完整实现后，用户至少能够：

1. 添加一个受支持的数据源并查看其基本信息。
2. 浏览数据、字段和语义说明。
3. 配置模型服务并创建分析会话。
4. 提出问题并获得可持久化的文本、数据或图表结果。
5. 展开计算依据核对结果。
6. 收藏一次分析，并在 Snippet 页面查看、重命名或取消收藏。
7. 归档、恢复或永久删除分析会话。
8. 重启应用后继续访问数据源、分析记录和设置。

当前阶段不以完成上述完整链路为验收标准，而以本地持久化读写正确、边界清晰和 main 可构建为准。

## 12. 后续演进方向

以下方向不代表当前承诺，实施前需要单独确认范围：

- 更多数据库、在线表格和内部数据源。
- 更完整的语义层和指标管理。
- 数据刷新、Snippet 重新生成和多格式导出。
- 报告、分享和协作能力。
- 更复杂的多步分析与可视化探索。
